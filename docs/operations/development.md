# Development

## Local mode (no database)

`npm install && npm run dev` opens the app on http://localhost:3000. Data lives in the browser (localStorage), as in AI Studio.

## Server mode (PostgreSQL + API)

1. Start a PostgreSQL 14+ and create the database as in [campus-deployment.md](campus-deployment.md) step 1, or run `docker compose up -d db`.
2. Copy `.env.example` to `.env` and set `DATABASE_URL` and `JWT_SECRET`.
3. In one terminal: `npm run server:dev` (API on port 8080, migrates on start when `MIGRATE_ON_START=true`).
4. Once: `npm run db:bootstrap -- --admin-password '<pw>' --class "Kelas Dev" --demo` (`--demo` adds the preset accounts shown on the login screen).
5. In another terminal: `VITE_API_URL=/api VITE_DEMO_MODE=true npm run dev`. Vite forwards `/api` to the API (`API_PORT`, default 8080).

## Tests

- `npm test`: unit tests, no database needed.
- `npm run lint`: TypeScript check.
- `TEST_DATABASE_URL=postgres://... npm run test:integration`: runs the API against a real PostgreSQL. **The tests drop and recreate the `public`, `private`, `auth` and `simrs_meta` schemas** of that database, so use a throwaway database.

## Where things live

| Path | Contents |
| --- | --- |
| `src/` | Ema's screens. They read and write data only through `useApp()` (`src/context/AppContext.tsx`). |
| `src/data-layer/` | Local or server persistence for each data slice, login session, polling for other users' changes. |
| `server/src/` | Express API: login, per-request transaction as the signed-in user, class data, roster import, audit log. |
| `db/migrations/` | Schema, row-level security, audit triggers. Add new files with a later timestamp; never edit an applied one. |
| `db/seed.sql` | Template class data, generated by `npm run seed:build` from `src/data/mockData.ts` and the master data. |

## Adding a table for a new screen

1. Add a migration in `db/migrations/` with the table (`class_id`, `id`, `data jsonb`, as the existing tables) add it to `private.clinical_tables()` so policies and triggers apply, and add a `public.table_modules` row naming its module(s) for the audit log. `db/migrations/20261023000800_master_data.sql` is a worked example.
2. Add the slice to `src/data-layer/slices.ts` and use `useSlice` for it in `AppContext`.
3. If the template class should have rows, add them in `scripts/build-seed.ts` and run `npm run seed:build`.
